## 1. Objetivo del proyecto

Scrapear `https://www.bcv.org.ve/` para capturar:

- Precio del **USD**, **EUR** y **CNY**
- La fecha **"Fecha Valor"** (fecha de la cotización publicada)

Requisitos del usuario:

1. Node.js vanilla + enfoque serverless, subido como API a **Netlify** para integrarlo a otros sistemas.
2. Scraper programado **2 veces al día**: mañana con hora **aleatoria entre 9:00–11:00** y tarde **aleatoria entre 16:00–17:00** (hora de Venezuela, VET = UTC-4).
3. Estar pendiente del "Fecha Valor": el BCV actualiza después de las 16:00, hay que detectar si ya salió el valor del día.

## 5. Cómo funciona

### 5.1 Scrapeo (`lib/parse.js` + `lib/bcv.js`)

La home del BCV trae todo en HTML plano (sin JS ni cookies), ~154 KB, responde en ~0.35s:

- Valores en bloques: `<div id="dolar">…<strong class="strong-tb">876,79760000</strong>` (mismo patrón con `id="euro"` e `id="yuan"`; también existen `id="lira"` e `id="rublo"` que NO se piden).
- Fecha: `Fecha Valor: <span class="date-display-single" content="2026-10-13T00:00:00-04:00">Martes, 13 Octubre 2026</span>` → se usa el atributo `content` (ISO) y el texto visible.

Detalles importantes:

- **Formato numérico venezolano:** coma decimal (`876,79760000`). `parseNumeric()` decide el separador decimal por el último separador encontrado (soporta `1.234,56` y `1,234.56`).
- Regex con anclaje `id="X"[\s\S]{0,1500}?strong-tb"` — cada `id` aparece **una sola vez** en la página (verificado). Si el BCV cambia el HTML, `parse()` lanza `No se encontraron datos en el HTML: ...` y el test `test/parse.test.js` falla (el build de Netlify corre `npm test`, así que un cambio de HTML **rompe el deploy** = alerta temprana).
- `scrape({retries, timeoutMs, delayMs})` con `AbortController`. La API usa `retries:2, timeout:4000`; los crons usan `retries:3, timeout:7000, delay:1000` (dentro del límite de 30s de las scheduled functions).

### 5.2 Crons y aleatoriedad (`lib/cron.js` + `netlify.toml`)

Los crons de Netlify son fijos y corren en **UTC** (VET = UTC-4, sin horario de verano), por eso:

| Función | Cron (UTC) | Ventana VET | Días |
|---|---|---|---|
| `scrape-morning` | `*/5 13-14 * * 1-6` | 09:00–10:55 | Lun–Sáb |
| `scrape-afternoon` | `*/5 20 * * 1-6` | 16:00–16:55 | Lun–Sáb |

La **hora aleatoria** se logra así: en el primer tick de cada ventana, la función **sortea un tick objetivo** (múltiplo de 5 min dentro de la ventana), lo guarda en Blobs (`slot:<fecha>:<periodo>`) y solo ejecuta el scrape cuando el reloj llega a ese tick. Los demás ticks hacen `skip` barato sin tocar el BCV.

- Slot de la mañana: 24 ticks posibles; tarde: 12 ticks.
- Después de ejecutar → `skip reason: ya_ejecutado`.
- Si el scrape **falla**, NO se marca ejecutado → el siguiente tick reintenta.
- **Pendiente de Fecha Valor:** si el periodo es `afternoon` y `actualizadoHoy=false` (el BCV aún no publicó hoy), **reintenta en cada tick hasta el fin de la ventana (17:00 VET)**. Eso detecta la actualización post-16:00.
- Fuera de ventana → `skip reason: fuera_de_ventana`.

Respuesta del cron (también va al log con prefijo `[bcv:morning]` / `[bcv:afternoon]`):

```json
{ "action": "scraped", "period": "morning", "dateKey": "2026-10-13",
  "objetivo": "09:15 VET", "intentos": 1,
  "rates": { "USD": 876.7976, "EUR": 982.00454402, "CNY": 131.03154748 },
  "fechaValor": "2026-10-13", "fechaValorTexto": "Martes, 13 Octubre 2026",
  "actualizadoHoy": true }
```

### 5.3 Almacenamiento (`lib/store.js`, store `bcv-rates`)

Claves planificadas en Netlify Blobs (store **`bcv-rates`**):

| Clave | Contenido |
|---|---|
| `latest` | `{ fetchedAtMs, payload }` — caché de 5 min para la API |
| `slot:<YYYY-MM-DD>:<morning\|afternoon>` | slot aleatorio del día: `targetVetMs, executed, attempts, fechaValor, updatedToday, lastError…` |
| `snap:<YYYY-MM-DD>` | histórico de snapshots del día (máx. 10 entradas) |

El store tiene fallback a `Map` en memoria si Blobs falla (la API sigue funcionando; solo pierde persistencia). Errores de Blobs se registran en `storageError` y por `console.error("[blobs] …")`.

## 6. Descubrimientos técnicos IMPORTANTES (no redescubrir)

### 6.1 El TLS del BCV está roto (certificado sin intermediate)

- **Síntoma:** `fetch` de Node y `https.request` fallan con `UNABLE_TO_VERIFY_LEAF_SIGNATURE` ("fetch failed"). `curl` en Windows SÍ funciona (schannel hace AIA fetching).
- **Causa:** `www.bcv.org.ve` sirve **solo el leaf** (`*.bcv.org.ve`, emitido por `Sectigo Public Server Authentication CA DV R36`, **vence 2026-11-20**) sin enviar el intermediate. OpenSSL/Node no hacen AIA fetching → la cadena no valida.
- **Solución implementada:** se descargó el intermediate desde su AIA (`http://crt.sectigo.com/SectigoPublicServerAuthenticationCADVR36.crt`, DER → PEM con `crypto.X509Certificate`) y se **incrusta como CA extra** en `lib/ca.js`, usada como `ca: [...tls.rootCertificates, EXTRA_CA]` en `lib/bcv.js`. NO se desactivó la verificación de certificados.
- Archivos: `certs/intermediate.crt` (DER original), `certs/intermediate.pem` (PEM).
- **Riesgo a monitorear:** el certificado del BCV **vence el 2026-11-20**. Si renuevan con otro issuer/intermediate y siguen omitiendo la cadena, el scrape fallará → re-descargar el nuevo intermediate desde la AIA del cert nuevo (mismo procedimiento, actualizar `lib/ca.js`).
- Nota: el camino por defecto (`tls.rootCertificates`) se mantiene; si el BCV arregla su cadena, sigue funcionando igual.

### 6.2 Netlify Scheduled Functions

Verificado en la docs oficial:

- Cron en **UTC** (5 campos, extensiones RFC; sin `@reboot`).
